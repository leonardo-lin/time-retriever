# 正样本 LoRA 检索器规格书

**状态：按此实现。**

本文件只规定这一项对照实验。原先的 `retriever` 完整微调、难负例、易负例、对比损失和排序损失都不在范围内，也不许改那些文件。

---

## 1. 目的

用 LoRA 微调同一个未来感知检索器，但监督只来自正例。给定当前 21 天负荷，它仍从 2025 年以前的历史库里找出若干历史窗口。这些窗口的未来应当对“预测接下来 7 天”有用。

和 `retriever` 比，这项实验只改训练配方：冻住 MOMENT 主干，只训适配器和投影；每条查询只拉近一个正例，不造任何负例。

训练过程要能在本地网页上实时看到损失曲线。

## 2. 不做的事

- 不改 `retriever/` 里的任何文件。
- 不预测 `\hat{Y}`，不训练生成器。
- 不把当前查询的真实未来 `Y` 送进编码器。
- 不计算、不抽样难负例或易负例。训练时也不算过去相似度。
- 不做 InfoNCE、排序损失、in-batch 负例，或任何“远离某条候选”的项。
- 不完整微调主干，不提供 `encoder=scratch`。
- 不做传统“只按过去相似度检索”的基线。

## 3. 检索器的输入和输出

与 `retriever/SPEC.md` 第 3 节相同。

| 阶段 | 检索器输入 | 检索器输出 | `Y` / `Yi` 的角色 |
| --- | --- | --- | --- |
| 训练 | 当前 `X`，以及抽出来的一个正例 `Xi` | 相似度 `R(X, Xi)` | `Y` 与 `Yi` 只用来挑选正例，不进入编码器 |
| 推理 | 当前 `X` | 最相近的若干 `Xi` | 选中 `Xi` 后，按行号从历史库查出 `Yi` |

因此：这仍是检索，不是“输入 `X`、输出 `Yi`”。

## 4. 数据

不新写读 CSV、切窗、泄漏检查。直接调用 `retriever.data.load_experiment`，切分规则与检索器规格第 4 节相同。

来源：`data/caiso_demand_forecast/SLD_FCST_ACTUAL.csv`  
只用 `CA ISO-TAC`。时间一律按加州本地时间。每天本地 23:00 取一条。

| 集合 | 规则 |
| --- | --- |
| 检索库 | 案例的 7 天未来必须在 2025-01-01 00:00 之前结束 |
| 训练查询 | 预测起点落在 2025 年，并且后面仍有完整的 7 天 |
| 验证 / 测试 | 预测起点落在 2026 年，随机打乱后按 50% / 50% 切开 |

程序必须检查：检索库里最晚的未来结束时间，早于第一条训练查询的预测起点。`load_experiment` 已经会停；本程序不得绕过这次检查。

一条案例：

```text
预测起点 t = 该案例的“现在”
X = [t-503h, ..., t]          21 天，504 小时
Y = [t+1h, ..., t+168h]       7 天，168 小时
```

验证损失仍记录并画在网页上。测试只在训练结束后做检索质量检查，不参与更新参数。模型按验证集 Top-5 未来相似度最高的一轮保存。

## 5. 正例

正例在训练前算好。它们只比较未来窗口形状，不依赖编码器参数，也不看过去相似度。

每条窗口先按自己的均值和标准差标准化。两条窗口的距离为：

```text
距离 = 0.5 × 标准化 MSE + 0.5 × (1 − 相关系数)
相似度 = exp(−距离 / temperature)
```

对每一条查询，把它和检索库中全部案例的未来比较：

```text
正例 = 未来相似度前 5%，且相似度 ≥ 0.75
若筛完没有正例，退回未来最像的那一条
```

每个训练步：每条查询从自己的正例池里抽 1 条。没有第二组候选。

评估时仍可用检索器那套难负例定义来报告“前 5 条里有多少是过去像、未来不像”。那是对照指标，不是训练信号。

## 6. 模型与损失

复用 `retriever.model.RetrieverEncoder`，但配置锁死：

```text
encoder = moment
freeze_backbone = true
use_lora = true
```

```text
504 小时
  → 左边补 8 个 0，变成 512；mask 标出补上的位置
  → MOMENT.embed(reduction="mean")，得到 1024 维
  → Linear(1024 → 128)
  → 单位向量
```

主干冻住。T5 的 `q` / `v` 加 LoRA。只训适配器和投影。投影学习率 1e-4，适配器 1e-5。默认 100 轮，按验证检索存最好的一轮。

两条单位向量的点积就是余弦相似度。损失只有一项：

```text
L = 1 − cosine(z(X), z(Xi+))
```

验证时用同一套正例抽样，但关闭 dropout，不反传。

已知限制：没有负例时，编码器可能把所有向量推到同一个方向，训练损失会接近 0，检索退化成随机。验证检索分数会暴露这件事。这一版不为此加正则或 in-batch 负例。

## 7. 监控

训练进程自己在 `127.0.0.1:8767` 打开网页，每秒刷新，不依赖外网。端口避开检索器的 8765 和生成器的 8766。

页面必须同时显示：

- 每个 batch 的训练损失
- 每一轮结束时的验证损失，以及验证检索的未来相似度
- 检索库、训练、验证、测试各有多少条，以及起止时间
- 训练结束后的测试检索结果

测试检索结果只比较“检索到的历史未来有多像”，与检索器规格第 7 节同一套对照：

| 对照 | 含义 |
| --- | --- |
| 本次检索器 | 用学到的余弦相似度取前 5 条 |
| 随机 | 随机取 5 条 |
| Oracle | 直接按真实未来相似度取前 5 条。这是上界，不能当作预测方法 |
| 难负例占比 | 前 5 条里，有多少属于“过去很像、未来不像” |

## 8. 程序分块

数据切分、编码器、检索评估从 `retriever` 进来，不复制。`positive_lora` 可以 import `retriever`；`retriever` 不许 import `positive_lora`。

```text
config      窗长、日期、正例门槛、LoRA、端口
positives   只按未来相似度生成正例下标
train       把上面几块串起来；损失写在这里
monitor     读训练日志并画网页
```

不新建 `data.py`、`model.py`、`loss.py`、`evaluate.py`、`sampling.py`。

模块之间只传递 `WindowSet`、正例下标列表，再加上自己的 `Config`。给 `load_experiment` 和 `RetrieverEncoder` 用时，把本实验的字段填进一份 `retriever.Config`；其中 `freeze_backbone` 和 `use_lora` 必须为真。

一次运行：

```text
train.main
  ├─ Config()
  ├─ 填成 retriever.Config → load_experiment
  ├─ positives.build_positives(train / val, database)
  ├─ RetrieverEncoder（LoRA，主干冻住）
  └─ 每一轮
        ├─ 每条查询抽 1 个正例 Xi
        ├─ 只把 X、Xi 送进编码器
        ├─ L = 1 − cosine
        ├─ evaluate_retrieval 算验证检索，升高才覆盖 encoder.pt
        └─ 结束后在测试集上报检索质量
```

每次运行单独存一份目录，里面有参数、数据切分摘要、逐步损失、验证检索最好的模型。

## 9. 怎样算做完

1. 检索库未来与查询起点之间的间隔大于 0，并打印出来。
2. 训练时网页上能看到训练损失和验证检索一起更新。
3. 测试检索给出检索器、随机、Oracle 三个未来相似度，以及难负例占比。
4. 整个过程不读取当前查询的 `Y` 作为编码器输入。
5. 训练循环里没有负例下标，也没有对比损失或排序损失。
6. `retriever/` 的 diff 为空。

## 10. 已确认的决定

下面几项按这次任务固定。要改实验时，改 `positive_lora/config.py` 里对应的值。

1. 只训正例。正例定义与检索器相同：未来相似度前 5%，且不低于 0.75；没有则退回未来最像的一条。
2. 损失就是 `1 − cosine`。没有负例项。
3. 编码器是本地 MOMENT-1-large + LoRA + 投影。主干冻住。投影 1e-4，适配器 1e-5。
4. 数据切分完全跟检索器走：检索库在 2025-01-01 之前，训练用 2025，验证和测试从 2026 随机对半切。
5. 按验证检索最好的一轮存模型。默认 100 轮。
6. 代码放在 `positive_lora/`，不碰 `retriever/`。
